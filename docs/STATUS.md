## Known gaps

Measured while writing tests; each is a program that does not compile or a method that is not mapped yet:

- `System.Array.Reverse`, `Sort`, `Clear` and `Resize` (the front end rejects the static methods: use `Array.rev`, `Array.sort`, `Array.fill`), `System.Array.CopyTo`
- a `seq` is a **strict list** here, not a lazy `IEnumerable`: a `seq { }` is built where it is made (by one loop) and not where it is read, so a sequence that is infinite (`Seq.initInfinite`, `Seq.unfold` without an end) or that has effects whose time matters does not behave as in .NET. The lazy sequence (state machines, `IEnumerator`) is the roadmap's "Sequence Expressions and Lazy Evaluation"
- multi-dimensional arrays (`Array2D.zeroCreate`, `a.[i, j]`) are rejected by the front end for this target: `let a = Array2D.zeroCreate<float> 3 4` fails with "Array2DModule.ZeroCreate is not supported" (found by FSharp.Wasm.Frame's tests; the library keeps flat arrays)
- `Map<'K,'V>` and `Set<'T>` as a declared type, a parameter or a record field, are `i32` for this target, so a program that hands a map to a function or keeps one in a record does not validate: `let count (m: Map<int,int>) = Map.count m` gives "type mismatch: expected (ref $type), found i32" (a map that is built and used inside one body works). Their instance members are not mapped either: `m.Count` is `FSharpMap__get_Count`, an unhandled import compiled to a Nop. Found 2026-11-24 by FSharp.Wasm.Actors (a pool of workers keeps its results in a map); the library keeps association lists until this is fixed, and goes back to `Map` then. The way to fix it: map `FSharpMap<K,V>` to the instantiation of the base library's `MapHandle<K,V>` (`registerGenericRecord` in `src/Core/Types.fs` makes one struct per instantiation), and the instance members to the `Map_*` functions of `Collections/Map.fs` with the map last (a property getter's arguments arrive as `[receiver; unit]`).
- `sprintf "%A"` / `%O` of a record, union, list or tuple (a compile error, not a wrong output); dictionary literals (`dict [ … ]`); comparer constructor overloads
- `StringBuilder.AppendFormat` with a format that is not a literal or has specifiers (`{0:N2}`): reported as unsupported
- a local function that is generic in its type arguments and whose only evidence of them is its use (`let bind r = match r with Ok v -> Ok (v + 1) | Error e -> Error e`, applied to a `Result<int, string>`) is compiled for `int`: annotate its parameter
- `async` and JSPI: planned
- the cost of a response that is a long string, in the compiled code itself (measured 2026-11-22, a profile of the Ghost Todo module on Node, a response of 218 000 characters, after the bulk string path below): 29.5 % garbage collection, 37 % writing the JSON (`Json.write`, `writeString`: the whole `Json` tree of 5 000 todos is built first, then written), 8.8 % the snapshot, 5.9 % `StringBuilder.Append`; our strings are arrays of i32 (4 bytes a character, where UTF-16 needs 2). Next to try: a JSON writer that appends to the builder without the tree, a builder that grows by doubling, and strings as arrays of i16 (the JS String Builtins read those, so the copy loop in `$host_strToHost` / `$host_strFromHost` would go too)
- `System.String(char[])` (the constructor of a string from an array of characters) is not mapped (WGC008)
- exceptions as values: an `exn` stored in a list or a record is typed as an integer (`[ System.Exception "x" ]` does not validate); `System.ArgumentException("x")` (a constructor that delegates to the primary one) leaves its second field out; a derived class that adds a field writes it to the base class's field (`inherit EqBase(name)` with an own `size`)
- two modules with the same name in different namespaces (`Browser.Css` of the runtime and a `Css` of another library) share one set of function names (`Css_color`): the first definition wins and a call to the other does not validate; name the modules differently
- an exception with a payload cannot be caught by type: `try … with MyError m -> …` receives no value (the JSON parser of fsharp-wasm-newsletter records its first error instead)
- a class that admits `null` (`[<AllowNullLiteral>]`) is a non-null reference for this target: a `null` passed or kept as a local or a parameter of that type does not validate (`type Chain(value: int, next: Chain)` and `Chain(3, null)` gives "expected (ref $type), found nullref"; found 2026-11-26 while checking the record fix below), so a chain that ends in `null` cannot be written, and `Unchecked.defaultof<'a>` at a string or a class is a null that traps when it is read into a local of that type (`let before = value` in a generic calc of text: "illegal cast"); a field of a class, an array or a `ResizeArray` in a record can hold null since 2026-11-26 (below), and an `isNull` of it is the test of the field. Use an option or an empty value until locals and parameters of such types are nullable
- `string` / `ToString()` of a case of a union that has fields prints the name of the case only (`string (Circle 1.5)` is `"Circle"`, .NET prints `"Circle 1.5"`; found 2026-11-26 while closing the item below), and the compiler says so once per union as a warning (WGC011); a case without fields prints as .NET does
- `Char.IsLetter`, `IsLetterOrDigit`, `IsUpper`, `IsLower` and `Char.ToUpper` / `ToLower` know ASCII only (the helpers `$charIsLetter` and the others test `A`..`Z` and `a`..`z`): `Char.IsLetter 'ä'` is false here and true on .NET (read from the helpers, 2026-11-26; not yet measured with a program, so there is no QuickTest for it)

Closed on 2026-11-26 (717 QuickTests pass; found by the arcs of FSharp.Graphics.Icons, whose points on a circle were off it by up to 4e-6 when compiled, and by nothing under .NET): `Math.Sin`, `Cos`, `Tan`, `Atan2` and `Exp` of a double were accurate to 1e-5 .. 1e-7, not to the 1e-16 of a double. Measured against JavaScript's `Math` over 0..7: `cos` off by 4.1e-6 near π, `sin` by 7.7e-7, `atan2(1, 2)` by 4.4e-8, `exp(-0.7)` by 7.4e-14. Why: `sin` and `cos` reduced to [-π, π] and summed the same few terms of the series there, which are not enough at π; the `atan2` series had six terms; the `exp` series seven, and its reduction rounded a negative argument toward zero, so that |r| reached ln 2 instead of half of it. The QuickTest `testMathAccuracy` holds 36 values, in every quadrant, close to multiples of π/2, negative and large (|x| = 100), to 1e-14 relative against the doubles of Python's `math`; it gives 0 without the change (checked by setting the change aside) and 11111 with it. The range is what it was: |x| below 1.3e10 for the trigonometric ones (a larger one is brought down by whole turns first), `exp` below ~709.

tools/               the CLI
tests/               the suites above
examples/            component-embed, component-linking
